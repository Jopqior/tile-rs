# Are the released Rust backend and Ascend host runtime/builder a complete Rust stack?

Checked **2026-09-28 UTC** against first-party release APIs, release bodies, tagged source, and the linked project documentation. **No publicly accessible release checked provides `ascend_rs` (the Rust/ACL host runtime) or `ascend_rs_builder` (`build.rs` kernel builder).** The available `tile-rs` asset is a Rust→MLIR *compiler backend*, not evidence of those host/build packages. Thus the published releases do **not** currently establish a complete Rust host + `build.rs` + Rust kernel replacement for the prototype's C++/ACL host. This is an availability finding, not proof that the packages do not exist privately.

## First-party ascend-rs project and remaining gap

The [project book](https://ascend-rs.org/en/print.html#33-the-build-system) explicitly describes `ascend_rs::prelude::*` for the host (`Acl`, device buffers, streams, `KernelLoader`) and `ascend_rs_builder::KernelBuilder` with `add_ascend_link_args()` in `build.rs`. It describes a Rust kernel → MLIR → generated AscendC C++ → `bisheng` pipeline; describing that design is **not** publication of installable crates. The book [links to `yijunyu/ascend-rs`](https://ascend-rs.org/en/) but its [repository](https://api.github.com/repos/yijunyu/ascend-rs) and [releases API](https://api.github.com/repos/yijunyu/ascend-rs/releases?per_page=100) both returned HTTP 404 unauthenticated. The alternative [`ascend-rs/ascend-rs` releases API](https://api.github.com/repos/ascend-rs/ascend-rs/releases?per_page=100) also returned 404. The tagged [tile-rs release workflow](https://github.com/yijunyu/tile-rs/blob/c3c8ec0169bd02757b51370ba9c6ec3b116b833d/.github/workflows/codegen-release.yml#L20-L58) identifies `yijunyu/ascend-rs-priv` as its **private** compiler source; its [public repository API](https://api.github.com/repos/yijunyu/ascend-rs-priv) returned 404 unauthenticated as expected. A 404 here means **not publicly inspectable via these URLs**, not proof of nonexistence or absence of private releases. The [crates.io API for `ascend_rs`](https://crates.io/api/v1/crates/ascend_rs) and [`ascend_rs_builder`](https://crates.io/api/v1/crates/ascend_rs_builder) also returned 404 when checked; this does not exclude other distribution channels.

**Next evidence needed before replacing the handwritten C++ host:** an accessible versioned release/source or SDK containing the actual `ascend_rs`/`ascend_sys` host runtime and `ascend_rs_builder`, their `Cargo.toml`s and CANN version requirements, an inspectable archive inventory, plus a runnable minimal host + `build.rs` + kernel example tested against the chosen hardware/camodel. The current macOS codegen tarball by itself does not meet that bar.
